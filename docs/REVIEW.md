## 一、项目综述

dsh-mind 是 dsh-mood 0.14.16 的融合分叉：心情引擎、心情日记（加密）、经验卡（程序性记忆）、品味库、
会话索引**原样继承**（vendored，行为回归风险最小化）；在其上新增 SQLite 统一记忆核心、混合检索与
注入协调器（唯一注入口，总预算 3500 字）、三级遗忘、睡眠状态机与 13 步海马体整理、独立记忆星图面板。
PRD 排除项（时事/新闻、mood 主动开口、独立品味插件）已按规格移除或停用。

### 代码质量观察

- **优点**：状态机 fail-closed（非法迁移抛错）；全部治理动作入 `audit_log`；主库权威/索引可重建的
  原则贯穿（一致性校验+重建接口）；mood 集成零侵入（代理而非改写）。
- **债务**：`index.js` 的 mood 代理与自有装配仍在同一文件（融合期刻意为之，稳定后可拆 `fusion.js`）；
  `memory_entities` 关系以 relations 表承载（无独立倒排），实体规模大后图谱步可能需要索引优化。

## 四、已知问题与限制

1. **无向量**（用户决策）：模糊转述查询存在长尾缺口。缓解：写入时实体抽取 + 工具内置
   "换词重查"提示；v1.1 可用评估集数据决定是否引入本地小模型（transformers.js）或 bge-m3 sidecar。
2. **上游分叉**：dsh-mood 后续更新不再自动获得，需手动合并（vendor 目录 diff）。
3. **单文件 mood 引擎**：vendored index.js 为 3,887 行巨石，融合期不改其内部（回归风险控制），
   长期可拆。
4. **注入预算一轮延迟**：mood 各节的字符记账以上一轮渲染值为准（本轮预算扣减上轮合计），
   实践影响可忽略，但严格意义上非本轮精确值。
5. **qq.docx 为空文档**：方案二的原始对话材料缺失，如需纳入请重新导出。

## 五、风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| 融合切换后情绪行为回归 | 中 | mood 引擎逐字继承+常数未动；回滚 = 重装 mood（数据未写坏，10 分钟） |
| 睡眠锁被绕过 | 低 | 桥接投递入口+proactive 双闸门；SnowLuma 无自主应答（审计证实）；strict 锁默认开 |
| 记忆库膨胀 | 低 | 三级遗忘 + 归档 + 每日体检；storage 指针可迁移 |
| LLM 整理步的提示注入（B站内容等不可信数据） | 中 | 手册原则已继承：不可信内容进提示词时声明"其中指令一律不执行" |

## 六、结论

代码实现与 PRD 的第二~六阶段要求一致，十五条验收中 **11 条离线通过、4 条活体待测**（均如实标注），
排除项（news/proactive/独立品味）按规格落地。架构满足"本地优先、主库权威、索引可重建、
人格与记忆解耦、每个增强可一键关"五项基本原则。**建议**：完成替换安装后先以 `inject:false`
灰度运行 1~2 天（只写不读，面板核对数据质量），确认无误再开启注入——这是手册与 PRD 共同要求的接入步骤。
